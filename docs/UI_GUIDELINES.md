# Trinetra Restaurant OS — UI Guidelines

## Visual Identity

The product is an operating system for restaurants, not an admin dashboard.

Screens must feel premium, intentional, and production-ready.

## Layout Principles

- Mobile first
- Tablet friendly
- Touch friendly
- Keyboard friendly
- Realtime where useful
- Fast and low-friction

## Interaction Principles

- Common actions should be visible
- Avoid nested menus
- Avoid unnecessary dialogs
- Minimize clicks
- Keep high-use workflows immediate

## States

Every important screen must support:
- Loading state
- Empty state
- Error state
- Success state

## Accessibility

- Do not rely on color alone
- Support keyboard usage
- Maintain readable contrast
- Use large enough touch targets

## Design Quality

No placeholder UI.
No toy templates.
No demo-only layouts.
No inconsistent spacing or component behavior.
